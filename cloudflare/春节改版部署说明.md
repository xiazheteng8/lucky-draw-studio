# 春节版 Cloudflare Pages 部署说明

## 原有站点升级
保留现有账号、数据库、KV、域名、环境变量与第三方平台配置。先备份，再升级源码。不要重新初始化站长或清空存储。

## 一键部署
安装 Node.js 后解压项目，在项目目录执行 `npm ci`。在当前终端设置 CLOUDFLARE_API_TOKEN，可另设 CLOUDFLARE_ACCOUNT_ID（多账户时必须指定）、CF_PAGES_PROJECT（默认 lucky）。执行 `npm run deploy:oneclick`。令牌仅从当前进程环境读取。

脚本会复用现有 CONFIG_KV，找不到时创建 giveaway-config；部署 Worker 后端，再为 Pages 的生产及预览环境设置 API_BACKEND 服务绑定，构建并发布 Pages。现有服务绑定和配置会合并保留。账户需要 Workers 编辑、KV 编辑、Pages 编辑权限；若启用 R2，还需 R2 编辑权限。

## 存储与绑定
- CONFIG_KV：KV 命名空间，用于站点配置、扫码相关状态和两个打赏主题的解锁记录。名称可以自定，绑定名必须保持 CONFIG_KV。
- REGISTRY：Durable Object，类 StudioRegistry，保存账号、配置、活动索引。
- ROOMS：Durable Object，类 DrawRoom，保存单个活动与开奖结果。迁移声明保留在 wrangler.jsonc。
- MEDIA：可选 R2 文件桶，用于上传自定义音乐。设置 ENABLE_R2=1 可让一键脚本创建并绑定，R2_BUCKET_NAME 默认 giveaway-media。未启用 R2 时自定义音乐上传不可用，内置音乐仍可使用。不是 S2。
- API_BACKEND：Pages 服务绑定，指向后端 Worker xia-zhe-teng-giveaway。后端密钥只放 Worker，勿放公开前端。

## 批量导入环境变量
复制 env-import.example.json 到自己的私有文件，填写需要的值。仅保留要导入的键，删除不用或已配置的键，避免覆盖旧值。通过 ENV_IMPORT_FILE 指向该文件后执行一键部署，脚本使用 Wrangler secret bulk 导入后端。

SITE_NAME：站点名称。STUDIO_ID：站点实例标识。SETUP_KEY：首次设置站长的一次性初始化密钥；已有站点勿重置。YOUTUBE_API_KEY：读取 YouTube 视频及评论。
ALLOW_PASSWORD_REGISTER、ENABLE_EMAIL_REGISTER、ENABLE_PHONE_REGISTER：注册方式开关。ENABLE_WECHAT_LOGIN、ENABLE_DINGTALK_LOGIN、ENABLE_TELEGRAM_LOGIN：第三方登录开关。
UNVERIFIED_ACTIVITY_HOURS：未验证用户的活动有效小时数。UNVERIFIED_RETENTION_HOURS：未验证活动记录保留小时数。
WECHAT_APP_ID / WECHAT_APP_SECRET：微信身份认证凭据。DINGTALK_CLIENT_ID / DINGTALK_CLIENT_SECRET：钉钉凭据。TELEGRAM_BOT_TOKEN / TELEGRAM_BOT_USERNAME / TELEGRAM_WEBHOOK_SECRET：TG 机器人及 Webhook 校验参数。SIGNIN_BASE_URL：扫码签到使用的 HTTPS 站点地址。

## Pages 手动配置
构建命令 npm run pages:build，输出目录 pages-dist。生产和预览环境分别配置 nodejs_compat、兼容日期 2026-10-30、API_BACKEND 服务绑定。不能仅拖放 public 目录，否则账号与抽奖 API 不会运行。GitHub Pages 只能托管静态页，不能代替本项目后端。

## 域名与平台回调
保留既有域名。首次部署时在 Pages 中添加自己的域名，按 Cloudflare 提示配置 DNS。微信、钉钉、TG 的合法域名、回调 URL、Webhook 必须匹配最终 HTTPS 域名；这些第三方平台配置无法只凭 CF 令牌自动完成。

## 验证
运行 npm run pages:build 和 npm run pages:test。然后实测登录、创建活动、名单导入、扫码、大屏、模拟开奖、两款付费主题的取消与确认解锁、各主题动画隔离、奖品保存和音乐。主题打赏当前使用用户自行确认付款，响应含 unverified=true，不宣称支付平台已核验。

## 搜索引擎
三个站点提供 robots.txt、sitemap.xml 和 about-site.html。部署后在 Google Search Console 添加各域名资源，按平台给出的 DNS TXT 验证，再提交各站 /sitemap.xml。缺少 Google 账号授权时不能代为完成账号内验证；提交也不保证收录时间。


## 邮件与短信发送变量补充
EMAIL_SENDER_URL：邮箱验证码发送接口地址；EMAIL_SENDER_TOKEN：该接口的授权令牌；EMAIL_SENDER_FROM：发件人标识。
PHONE_SENDER_URL：手机验证码发送接口地址；PHONE_SENDER_TOKEN：该接口的授权令牌；PHONE_SENDER_FROM：短信签名或发送方标识。
BASE_URL：站点公开地址，SIGNIN_BASE_URL 未设置时用于扫码地址回退。需与最终 HTTPS 域名一致。

## 已部署实例与代理层
本次保留原有 KV、Durable Objects、环境配置、账号和数据卷。生产 Worker 没有 MEDIA/R2 绑定，因此保留原有“未启用 R2 时无法上传自定义音乐”的状态；需要该功能时再启用 R2。
三个 VPS 域名的 SEO 路由由 1Panel/OpenResty 的 00-seo.conf 管理。已将 robots.txt 和 sitemap.xml 改为代理到对应应用，防止旧 alias 文件覆盖新站点地图。

## 验证范围
当前账户的 Worker、Pages 及 VPS 已实际部署，并通过公网读取检查；新账户的“一键创建资源”分支未使用另一个新账户实测，运行前应核对令牌权限。微信公众号、小程序发布、钉钉及 TG 授权回调需要对应平台账号，安装包不能替代第三方审核。


## 带说明模板的填写方法
环境变量批量导入模板的每个引号内均包含用途和示例。导入前必须将整个说明替换为实际值：例如 ALLOW_PASSWORD_REGISTER 的值改为 "true"，UNVERIFIED_ACTIVITY_HOURS 改为 "24"。不使用或需要保留线上原值的变量，请删除对应整行；同时保持合法 JSON，最后一项后不要保留逗号。不要把说明文字当作配置值直接导入，也不要填入虚构的第三方密钥。
